# Tapeless: план

## 1. Ціль і для кого

Допомогти українцю визначитись із професією чи діяльністю: від школяра й студента до тих, хто змінює сферу.
Сайт не дає вердикт сам (немає бази професій і не може бути «правильної»), а **складає якісний запит до ШІ**:
з профілем людини, чіткими питаннями й вимогою перевіряти факти. Користь — у структурі: людина часто не знає,
що саме питати (конкуренція, захищеність від ШІ, шлях людей, що вже це зробили).

Гіпотези (щоб міряти успіх):
- **Г1.** Людина доходить до готового промпта менше ніж за 5 хвилин у швидкому режимі й за 10 у докладному.
- **Г2.** Хоча б 40 % тих, хто дійшов до результату, натискають «Відкрити в …» чи «Копіювати» (міряємо подіями
  GA4 лише в тих, хто дав згоду; див. п. 8).
- **Г3.** Сторінки професій приводять органічний пошуковий трафік (довгий хвіст на кшталт «чи варто йти в …»).
- **Г4.** Візуальна мова Poklych читається на телефоні й без реклами тримає увагу (побічна мета: перевірити стиль).

## 2. Потік екранів

Одна сторінка-майстер (`/`), крок за кроком, стан зберігається в пам'яті сторінки (і за згодою — у `localStorage`).
Прогрес угорі («Крок 2 з 5»), на кожному кроці «Пропустити» й «Не знаю» (це теж сигнал для промпта).

1. **Що цікавить.** Поле вільного тексту («Що Вам цікаво? Чим не набридло б займатись?») + заготовлені картки
   (чекбокс-чипи, групами: люди, цифри й логіка, слова, творчість, руки й техніка, природа й тварини, здоров'я,
   технології, навчання, бізнес, спорт, безпека). Мінімум одна картка або текст, щоб іти далі (або «Поки не знаю»).
2. **Що вмієте.** Картки умінь тими самими групами; кожна — перемикач рівня «трохи / добре / сильно». Поле «Інше».
   Окремо: мови (укр/англ/інші з рівнем), освіта, робочий досвід одним реченням.
3. **Про Вас.** Стать (чоловік / жінка / інше / не вказувати), вік (число або діапазон), місто чи країна,
   «готові переїхати» (ні / в Україні / за кордон), віддалена робота. Необов'язкове чутливе: військовий облік
   (військовозобов'язаний / ні / не вказувати; за замовчуванням «не вказувати») — лише щоб ШІ врахував бронювання
   й обмеження виїзду. Поруч підказка, чому питаємо й що нічого не зберігається.
4. **Умови.** Повзунки й перемикачі:
   - баланс життя й роботи (більше життя ↔ більше роботи);
   - навчання: «без навчання» / «короткі курси» / «диплом» / «готовий(а) на будь-що»;
   - небезпека й ризик: «лише безпечне» / «помірний» / «ризик припустимий»;
   - стрес і темп; режим (офіс / віддалено / поле / змішано); команда чи сама / сам; графік (стабільний / змінний);
   - розумова чи фізична праця; публічність (готов(а) показувати обличчя чи ні);
   - дохід (мінімум для життя, цільовий, «неважливо») і за який строк, стартовий капітал;
   - поєднання з блогерством (так / ні / цікаво), важливість захищеності від ШІ (1–5).
5. **Результат.** Повний промпт (прев'ю, що можна відредагувати), чотири кнопки «Відкрити в Claude / ChatGPT /
   Gemini / Perplexity», «Копіювати промпт», «Копіювати коротку версію», режим відповіді (див. 4.3), «Редагувати
   відповіді» і посилання «Поділитись налаштуваннями» (стан у `#hash`, без сервера).

Швидкий режим: кроки 1, 2 і 4 скорочені до 5 полів (інтерес, уміння, вік, місто, баланс); решта береться як «не вказано».

## 3. Дані

Усе в `data/*.json` (ніякого API): `interests.json`, `skills.json`, `presets.json`, `services.json`
(сервіси ШІ й схеми посилань), `professions.json` (для SEO-сторінок, фаза 2). Рядки інтерфейсу — `i18n/uk.json`
(структура під майбутню англійську). Початкові картки — `content-seed.md`.

Схема профілю (єдине джерело для промпт-білдера й посилання `#hash`):

```
profile = {
  interests: { text, cards: [id] }, skills: { text, cards: [{id, level}] },
  languages: [{code, level}], education, experience,
  person: { gender, age, location, relocate, remote, military },
  conditions: { balance, study, risk, stress, mode, team, schedule, workType, publicity,
                income: { min, target, horizonMonths }, capital, blogging, aiPriority },
  extra: string, mode: "explore" | "deep_dive" | "compare", clarify: "ask_first" | "assume"
}
```

Усе, чого людина не вказала, у промпт не потрапляє зі значенням — потрапляє як «не вказано: запитай мене, якщо це
важливо» (залежно від `clarify`).

## 4. Генерація промпта

Чиста функція `buildPrompt(profile, options) → { full, short }` в окремому ES-модулі без залежностей від DOM;
тести — `node --test` (вбудований, без пакетів). Шаблони, секції й правила — `llm-prompt-template.md`.

### 4.1 Посилання на сервіси

Налаштовується в `data/services.json`, а не в коді. **Схеми посилань змінюються, тож перед релізом перевірити кожну
вручну**; станом на сьогодні відомо (не гарантовано):

| Сервіс | Передзаповнення | Примітка |
|---|---|---|
| Claude | `https://claude.ai/new?q=<encoded>` | пошук 2026-10-19 не підтвердив, чи вебверсія досі підтримує `q`; десктопний `claude://claude.ai/new?q=` підтримує (до ~14 000 символів) |
| ChatGPT | `https://chatgpt.com/?q=<encoded>` | зазвичай працює; довгі запити можуть обрізатись |
| Perplexity | `https://www.perplexity.ai/search?q=<encoded>` | зазвичай працює; це пошукова система — підходить для частини про людей і джерела |
| Gemini | офіційного параметра немає | копіюємо промпт у буфер і відкриваємо `https://gemini.google.com/app`, показуємо «Вставте (Ctrl/⌘+V)» |

Правила: (1) завжди спершу копіюємо повний промпт у буфер; (2) якщо закодований URL довший за поріг із
`services.json` (типово 1800 символів), у посилання йде **коротка версія**, а повну людина вставляє сама; (3) на
сервісі, де передзаповнення не гарантоване, кнопка підписана «Відкрити й вставити»; (4) жодних токенів і акаунтів.

### 4.2 Структура промпта (стисло)

Роль → профіль людини → завдання (список із запиту нижче) → правила чесності → формат відповіді → режим
(питання спершу чи припущення). Повний текст — у `llm-prompt-template.md`.

Що ШІ має розібрати по кожній із 5–7 професій: суть роботи без романтики; **стереотипи проти реальності**;
складнощі й вигорання; шлях входу (строк, вартість, навчання); **аналіз конкуренції** (попит, насиченість, ринок
в Україні й віддалено); діапазон доходу з застереженнями; безпека й ризик; реальний баланс; **поєднання з
блогерством і відомі блогери** (лише ті, у кого впевнений, з платформою; інакше — запити для пошуку); **захищеність
від заміни ШІ** (за задачами, з горизонтами й невизначеністю); **люди, що побудували в цьому кар'єру**, і як знайти
й вивчити їхній шлях; ризики плану й перші дешеві експерименти.

### 4.3 Режими відповіді

- **Дослідити** (типово): 5–7 професій + порівняльна таблиця + топ-3 з поясненням.
- **Заглибитись:** одна професія, яку людина вже обрала (з поля), докладніше + 30/90/180 днів.
- **Порівняти:** 2–3 професії, які людина називає.
- **Спершу питання** (типово): ШІ ставить 5–7 уточнювальних питань і чекає; **Без питань:** робить припущення й
  перелічує їх.

## 5. Пошук людей, які вже зробили цю кар'єру

Окремий розділ у результаті й у промпті (це ключова цінність — приклади краще за поради):

- де шукати: LinkedIn (запит «посада + країна»), YouTube («день із життя», «як я став(ла)…»), подкасти й інтерв'ю
  (DOU, AIN, Mind, Forbes UA, Rubryka — якщо доречно), Telegram-канали, Threads / Instagram / TikTok, Reddit,
  Habr/Medium для технічних; профспільноти й чати;
- що витягати: з чого починали, скільки йшло, переломні моменти, помилки, дохід у діапазоні, чи був диплом, що
  вирішило;
- як звернутись: шаблон короткого повідомлення для «інформаційного інтерв'ю» (3 питання, без прохання про роботу);
- ШІ не вигадує імена: або називає, коли впевнений (з позначкою «перевірте»), або дає пошукові запити й критерії;
- у самому інтерфейсі: до кожної професії (фаза 2) — готові пошукові посилання (`google.com/search?q=…`,
  `youtube.com/results?search_query=…`) без трекерів.

## 6. SEO

Сайт статичний, тож ключове — індексованість сторінок і швидкість.

- **Сторінки:** `/` (майстер + текст для індексації: що це, як працює, FAQ), `/how-it-works/`, `/about/`
  (книга й ідея), `/privacy/`, `404.html`. **Фаза 2:** `/professions/<slug>/` — сторінка на професію з реальним текстом
  (стереотипи, складнощі, шлях, ШІ) і кнопкою «Промпт для цієї професії» (профіль із передзаповненою професією).
  Генерація — `scripts/build.py` (стандартна бібліотека), результат комітиться.
- **Технічне:** `<html lang="uk">`, унікальні `<title>` і `meta description`, `canonical`, Open Graph й Twitter
  (статичне OG-зображення 1200×630), JSON-LD (`WebSite`, `WebApplication`, `FAQPage`, `BreadcrumbList`,
  `Article` для сторінок професій), `sitemap.xml`, `robots.txt`, семантична розмітка (`main`, `nav`, `h1` один на
  сторінку), адекватні URL, внутрішня перелінковка між сторінками професій.
- **Адреса й шляхи:** сайт на `https://doutivity.github.io/tapeless/` (підкаталог проєктного сайту) — усі посилання
  відносні або від `site.config.json:basePath` (`/tapeless/`); канонічна адреса, `og:*`, `sitemap.xml` і `manifest`
  (`start_url`, `scope`) — від `siteUrl` (`https://doutivity.github.io/tapeless`).
- **Увага: `robots.txt` у підкаталозі пошукові роботи ігнорують** — вони читають лише `https://doutivity.github.io/robots.txt`
  (корінь хоста), який належить користувацькому сайту `doutivity.github.io`, а не цьому репозиторію. Тож: (1) файл усе одно
  кладемо (правильний вигляд, готовність до власного домену); (2) індексацією реально керують `<meta name="robots">` на
  сторінках і `sitemap.xml`; (3) `sitemap.xml` подаємо в Google Search Console (властивість «префікс URL»
  `https://doutivity.github.io/tapeless/`, підтвердження мета-тегом або HTML-файлом) і Bing Webmaster Tools; (4) за бажанням додати
  рядок `Sitemap:` у `robots.txt` кореня в репозиторії `doutivity.github.io`.
- **Швидкість:** до згоди на аналітику без зовнішніх запитів, Onest підмножини (cyrillic + latin, 400/700), `font-display: swap`,
  критичний CSS інлайном, JS < 40 КБ, LCP < 1.5 с на 4G, Lighthouse ≥ 95 за всіма пунктами.
- **Без JS:** сторінка читається й має зміст (`<noscript>`: пояснення + посилання на ручний шаблон промпта).

## 7. Дизайн (стиль Poklych)

Беремо «М'яку Тишу»: світла й темна теми, Onest, закруглені картки, м'які тіні, один акцент. Джерело —
`design-source/` (`tokens.css` — змінні тем; `base.css` — типографіка й каркас; `components.css` — кнопки, картки,
чипи, бейджі, поля, смуги прогресу). Адаптувати, а не копіювати все: адмінські змінні (`--ch-*`, `--site-*`,
`--brand-*`, `--dev*`, `--staging*`) не потрібні.

- Теми: за `prefers-color-scheme` + ручний перемикач (`data-theme="light|dark"` на `<html>`, вибір у `localStorage`,
  без блимання при завантаженні — крихітний інлайн-скрипт у `<head>`).
- Власні елементи: **стрічка** (діагональні жовто-чорні смуги `--tape-yellow`/`--tape-black`) — як тонкий розділювач
  під шапкою й рамка результату; знак — проста іконка касети/котушки в SVG (власна, не соняшник Poklych); у підвалі
  «зроблено в стилі Poklych» з посиланням, без нав'язливості.
- Картки вибору — великі цільові зони (≥ 44 px), чіткий стан «вибрано» (не лише колір), клавіатура: стрілки/Space.
- Мобільна версія першочергова: один стовпець, `--page` ≈ 560 px, нижня панель «Назад / Далі» липка.
- Доступність: WCAG AA, видимий фокус, `aria-live` для прогресу, `prefers-reduced-motion`, мова українська скрізь.
- Тон: на «Ви», спокійно, без емодзі в кнопках; емодзі лише на картках інтересів (за потреби).

## 8. Приватність і чесність

- Нуль власних серверів. **Аналітика — Google Analytics 4 (GA4) лише після згоди**, див. «Аналітика й згода» нижче.
  Без згоди сторінка не робить жодних запитів до Google (скрипт навіть не завантажується).
- `localStorage` — лише за згодою («Запам'ятати відповіді на цьому пристрої»), кнопка «Стерти».
- Чутливі поля (стать, військовий облік) — необов'язкові, пояснено, навіщо; у промпті формулюємо нейтрально й
  просимо ШІ **не підбирати професію за статтю чи віком, а враховувати лише реальні обмеження й закони**.
- Застереження на результаті: ШІ помиляється, цифри й імена перевіряйте, це не порада юриста чи психолога.

### Аналітика й згода (Google Analytics 4)

Мета — міряти гіпотези Г1–Г3, а не стежити за людьми. Вимоги:

- **Попередження до збору.** Перед першим візитом до GA на сторінці банер-попередження (за стилем Poklych, не модальне
  вікно на весь екран): що саме збираємо, навіщо, хто обробляє (Google), що можна відмовитись. Три однаково помітні
  кнопки: «Прийняти», «Відхилити», «Налаштувати» (прості перемикачі; крім аналітики іншого необов'язкового немає).
  Жодних попередньо вибраних згод і «темних патернів».
- **До згоди — нуль запитів до Google.** `gtag.js` не підключається, `dataLayer` порожній. Режим згоди (Consent Mode v2)
  використовуємо як страховку: усі прапорці (`analytics_storage`, `ad_storage`, `ad_user_data`, `ad_personalization`)
  за замовчуванням `denied`; після «Прийняти» — лише `analytics_storage: granted`, реклама лишається `denied` (реклами
  немає). Після «Відхилити» — нічого не завантажуємо.
- **Вибір зберігається** в `localStorage` (ключ `tapeless:consent`, значення + дата + версія тексту згоди). Змінилась версія
  тексту чи минуло 12 місяців — питаємо знову. Відкликати можна будь-коли: посилання «Налаштування аналітики» у підвалі
  на кожній сторінці; відкликання видаляє cookie `_ga*` і дозапис припиняється.
- **Ідентифікатор вимірювання** (`G-…`) — у `site.config.json:analytics.measurementId`. Порожній — аналітика вимкнена, банера
  немає, у `privacy` не згадується GA.
- **Що не надсилаємо:** жодних відповідей форми, тексту промпта, інтересів, віку, статі, локації, військового обліку, `#hash` з
  профілем (адресу сторінки для GA очищаємо від `#`; `page_location` без фрагмента). Лише знеособлені події:
  `wizard_start`, `wizard_step` (номер кроку), `wizard_complete` (режим швидкий/докладний), `prompt_copy` (повний/короткий),
  `service_open` (`claude|chatgpt|gemini|perplexity`), `theme_change`, `consent_change`. Без користувацьких ідентифікаторів
  (`user_id` не використовуємо), IP-анонімізація GA4 увімкнена за замовчуванням, зберігання даних — мінімальне (2 міс.) у
  налаштуваннях ресурсу GA.
- **Сторінка «Конфіденційність»** оновлюється: що збирає GA, на яких умовах, як відмовитись, як змінити вибір, контакт, дата й версія.
- **Тони й доступність банера:** українською, на «Ви»; фокус на банері при появі без захоплення (не блокує сторінку), `role="dialog"`
  з `aria-labelledby`, клавіатурна навігація, не перекриває основну кнопку на 360 px (прилипає знизу компактно), поважає
  `prefers-reduced-motion`.
- **CSP.** GitHub Pages не дає заголовків, тож за потреби `<meta http-equiv="Content-Security-Policy">`; у ньому домени Google
  потрібні, але сам скрипт вантажиться лише після згоди.

## 9. Покращення, які варто врахувати

- **Режим «Не знаю»** на кожному кроці: промпт тоді просить ШІ допомогти з цього питання, а не мовчки пропускає.
- **Режими «дослідити / заглибитись / порівняти»** і вибір «спершу питання / без питань» (п. 4.3).
- **Короткий і повний промпт** (для лімітів URL) + редагований прев'ю: людина бачить, що відправляє.
- **«Поділитись налаштуваннями»:** профіль у `#hash` (base64url JSON), можна надіслати другові чи повернутись.
- **Перевірка реальності:** пошукові посилання на вакансії й зарплати (Work.ua, Robota.ua, DOU, Djinni, LinkedIn) на
  сторінках професій і в блоці «що перевірити самому».
- **Експерименти замість рішення:** промпт просить 2–3 дешевих тести на тиждень (інформаційне інтерв'ю, мініпроєкт,
  день на практиці) і критерії «що я зрозумію з цього».
- **Українські реалії:** воєнний стан, мобілізація, бронювання, релокація, ФОП і податки, дистанційний ринок, курси
  й програми (державні й приватні) — окремий короткий блок у промпті.
- **Другий раунд:** після відповіді ШІ — підказка наступних запитів («Розпиши план на 90 днів для №2», «Знайди 10 людей
  для інформаційних інтерв'ю»).
- **Розділ «Для батьків і вчителів»** (фаза 3): інший вхід — про дитину, без чутливих полів.
- **Англійська версія** (фаза 3): `i18n/en.json`, `hreflang`; структура закладена одразу.
- Не робимо: акаунти, рейтинги професій «за версією сайту», зарплатні таблиці власного виробництва, рекламу.

## 10. Макети й артефакти

Реалізація починається з **макетів**, як у Poklych (`docs/design/`): самодостатні HTML-галереї без збірки, у яких кожен візуальний
елемент показано 3–9 варіантами в масштабі, де він живе (телефон 390 px і десктоп 1280 px, світла й темна тема); обирає власник,
реалізується лише обране. Макети лежать у `design/` і лишаються в репозиторії.

## 11. Ризики

| Ризик | Що робимо |
|---|---|
| Схема URL сервісу ШІ змінилась | `services.json` + «копіювати» завжди першим; ручна перевірка перед релізом, нотатка дати перевірки |
| Довгий промпт не влізає в URL | короткий варіант у посиланні, повний — у буфері |
| ШІ вигадує імена блогерів і цифри | вимоги чесності в промпті, позначки впевненості, пошукові запити замість імен, застереження на сайті |
| Аналітика без чесної згоди (ePrivacy/GDPR, відвідувачі з ЄС) | банер до збору, нуль запитів до Google без згоди, рівнозначні кнопки, відкликання в підвалі, події без даних форми, оновлена `privacy` |
| Чутливі дані (військовий облік, стать) | необов'язково, нічого не зберігаємо й не надсилаємо, нейтральне формулювання |
| Стереотипи в підказках | промпт забороняє підбір за статтю/віком, лише за інтересами, уміннями, обмеженнями |
| Розпорошення (проєкт-відволікання від Poklych) | тайм-бокс: фаза 1 — 3–4 дні, фаза 2 — окремо за потреби |
| Назва зайнята / плутається | перевірити репозиторій і домен; запасні назви в README |
| Дрібні пошукові позиції | сторінки професій із реальним змістом, а не шаблонними; не більше 15–20 на старті |

## 12. Віхи
